# Combat_BattleShadows — 전투 헥스 그림자

ERM에서 전장의 원하는 헥스에 파이어볼 조준 때와 같은 그림자를 깔고, 그 칸의 부대에 깜빡이는 하늘색 테두리를
켜는 ERA 플러그인입니다. 화면 표시만 바꾸므로 네트워크 전투에서도 동기화 문제가 없습니다.

설치 파일은 `Combat_BattleShadows.era` 하나입니다. 게임의 `Mods\WoG\eraplugins\`(또는 쓰는 모드의 `eraplugins`)
폴더에 넣습니다.

## 어떻게 빠르게 그리나

전장을 다시 그리지 않습니다. 게임이 이미 만들어 둔 화면 그림 위에서 그림자 칸의 땅만 어둡게 만들고, 바뀐 사각형만
화면으로 보냅니다(데몬의 `Interface_SpellsDescription` 연쇄 마법 표시와 같은 방법). 그래서 그림자가 커서처럼 바로
움직입니다. 부대와 장애물은 어두워지지 않고 그림자 위에 그대로 보입니다.

예외는 **테두리가 바뀔 때**입니다. 부대 테두리는 부대를 다시 그려야 나타나거나 사라지므로, 테두리 대상이 바뀌는
순간에만 전장 전체를 한 번 다시 그립니다.

## ERM 함수

ERA는 `!!FU(이름):P`를 같은 이름으로 등록된 플러그인에도 전달합니다. 아래 함수들은 ERM 쪽에서 `!?FU(...)`를
따로 만들지 않고 바로 호출합니다. 헥스 번호는 `줄 × 17 + 칸`이고, 0칸·16칸(영웅 자리)은 무시합니다. 그래서
생략한 값(0)도 무시됩니다.

| 함수 | 인자 | 하는 일 |
|---|---|---|
| `BattleShadow_Follow` | 반경(0~4, -1 끔) / 테두리(1) | 마우스가 있는 칸 둘레를 플러그인이 직접 따라가며 칠함 |
| `BattleShadow_Radius` | 헥스 / 반경(0~4) / 테두리 | 지정한 칸 둘레를 칠함 |
| `BattleShadow_Hexes` | 헥스 x1~x10 / 테두리(x11) | 적은 칸만 칠함. -1은 빈자리 |
| `BattleShadow_Stacks` | 헥스 x1~x10 / 테두리(x11) | 그 칸에 서 있는 **부대 전체**(2칸 부대는 두 칸 모두)를 칠함. 연쇄 마법용 |
| `BattleShadow_SkipStacks` | 헥스 x1~x16 | 그 칸에 서 있는 부대는 어떤 그림자·테두리에서도 **빠짐**. 마법이 안 통하는 부대용 |
| `BattleShadow_Clear` | 없음 | 모두 지움 (따라가기 포함) |
| `BattleShadow_Debug` | 결과 9개 | 진단용 (아래 참고) |

반경별 칸 수: 0 = 그 칸만, 1 = 7칸(파이어볼), 2 = 19칸, 3 = 37칸, 4 = 61칸.

## 언제 지워지나

| 때 | 지워지는 것 |
|---|---|
| MM0 트리거가 다시 시작될 때 | `Radius`, `Hexes`, `Stacks`, `SkipStacks` (따라가기는 유지) |
| 커서가 MM0 없이 다른 칸으로 갈 때 | `Radius`, `Hexes`, `Stacks` |
| 전투 행동 시작, 전투 시작/끝, 게임 종료/불러오기 | 전부 (따라가기 포함) |

같은 MM0 안에서 여러 함수를 부르면 모양이 합쳐지고, 화면은 MM0가 끝난 뒤 한 번만 바뀝니다. `SkipStacks`는 MM0가
끝난 뒤에도 따라가기에 계속 적용되므로, MM0마다 다시 불러 주면 됩니다.

## 사용 예

### 범위 지속 마법 (버서크 같은 것)

```erm
!?MM0;
!!FU(BattleShadow_Follow):P-1;                  [일단 끔]
!!SN:W^Ready_to_Cast_spell_by_Mod^/?y7;
!!FU&y7=0:E;                                    [주문 준비 중이 아니면 끝]
!!FU(BattleShadow_Follow):Pv495/1;              [반경 v495로 마우스를 따라감, 테두리 켬]
!!re i/0/41;                                    [모든 부대를 보며]
  !!BMi:N?y30;
  !!co&y30<=0;                                  [없는 부대는 건너뜀]
  ; 여기서 이 마법이 부대 i에게 안 통하면 y31=1 (아군에게 저주, 면역 등 모드 규칙대로)
  !!BMi:P?y32;                                  [부대 위치 헥스]
  !!FU(BattleShadow_SkipStacks)&y31=1:Py32;     [안 통하는 부대는 그림자에서 뺌]
!!en;
```

### 연쇄 마법 (두 부대에 연속으로)

```erm
!?MM0;
; y1 = 첫 번째 대상 부대 위치, y2 = 두 번째 대상 부대 위치 (모드 규칙대로 계산, 없으면 -1)
!!FU(BattleShadow_Stacks):Py1/y2/-1/-1/-1/-1/-1/-1/-1/-1/1;
```

## 진단: `BattleShadow_Debug`

MM0 트리거 맨 끝에 아래 두 줄을 넣으면 전투 화면 아래 힌트 줄에 상태가 표시됩니다.

```erm
!!FU(BattleShadow_Debug):P?y20/?y21/?y22/?y23/?y24/?y25/?y26/?y27/?y28;
!!MM:M^v%y20 shown=%y21 hint=%y22 follow=%y23 skip=%y24 paints=%y25 fast=%y26 full=%y27 cursor=%y28^;
```

| 표시 | 뜻 |
|---|---|
| `v` | 플러그인 버전(지금 6). 0이면 플러그인이 호출되지 않은 것 |
| `shown` | 지금 화면에 칠해진 헥스 수 |
| `hint` | 이번 MM0에서 `Radius`·`Hexes`·`Stacks`로 요청한 헥스 수 |
| `follow` | 따라가기 반경. -1이면 꺼짐 |
| `skip` | `SkipStacks`로 받은 헥스 수 |
| `paints` | 이번 전투에서 그림자를 칠한 횟수 |
| `fast` | 전장을 다시 그리지 않고 바뀐 부분만 보낸 횟수 |
| `full` | 테두리 때문에 전장 전체를 다시 그린 횟수 |
| `cursor` | 플러그인이 보는 커서 헥스 |

## 개발자용 메모

- 화면 그림은 `H3WindowManager::GetDrawBuffer()`(창 캔버스)입니다. 그림자 칸의 원래 픽셀을 저장한 뒤 칠하고,
  나중에 **아직 우리가 칠한 값 그대로인 픽셀만** 되돌립니다(`Interface_SpellsDescription`의 PixelBackup을 옮겨
  씀). 그사이 게임이 그린 부대 애니메이션 등은 지우지 않습니다.
- 화면 갱신은 `WindowManager::H3Redraw`(`0x603190`)로 바뀐 사각형만 보냅니다. 같은 함수에 HiHook을 걸어, 게임이
  우리 칸과 겹치는 영역을 내보낼 때마다 그림자를 다시 얹습니다.
- 부대 그리기(`0x43DE60`)에도 HiHook을 걸어, 그리기 전에 그림자를 걷고 그린 뒤 다시 칠합니다. 두 번 어두워지는
  일을 막고, 부대가 다시 그려질 때 땅을 복원해도 그림자가 남게 하기 위해서입니다. 경계 측정 중(`+0x13D34`)에는
  손대지 않습니다.
- 땅인지는 캔버스 픽셀이 전장 배경판(`combat->drawBuffer`)의 같은 자리 픽셀과 같은지로 판단합니다. 둘이 맞지
  않는 환경(15% 미만 일치)이면 칸 전체를 칠합니다. 이 판단은 전투마다 한 번 합니다.
- 칠하는 모양은 `CCellShd.pcx`를 헥스 틀로 씁니다. 픽셀이 Heroes 3 특수 팔레트 번호(0 투명, 1~2 가장자리,
  3~4 몸통)라서 그 비율만큼 검게 섞습니다. 16비트(게임 색 마스크)와 HD 32비트를 모두 처리합니다.
- 마우스 이동은 전투 화면 메시지 처리 함수(`0x4746B0`)의 HiHook에서 받습니다. 요청과 화면이 달라졌을 때만
  칠합니다. MM0 안에서 부른 함수는 ERA의 `OnBattleMouseHint_Quit` 이벤트나 메시지 처리 끝에서 한 번에 반영합니다.
- 테두리는 `0x43ED00`(`H3CombatCreature::highlightContour`)으로 켜고, 대상이 바뀌면 `0x493FC0`으로 전장을 한 번
  다시 그립니다. 게임이 이미 켜 둔 테두리는 건드리지 않습니다.
- 반경 계산은 직접 합니다. 어느 줄이 오른쪽으로 밀려 있는지는 실제 헥스 위치(`squares[].left`)에서 읽습니다.
- 주소와 시그니처는 저장소의 `Interface_SpellsDescription`(h3era.exe로 확인됨), `Combat_SwitchingCreatureAction`과
  같습니다.
